# Reports

Everything in this folder is generated from an actual run on this machine, and regenerated by a
script — none of it is written by hand.

| Report | Produced by | Covers |
|---|---|---|
| [TEST_REPORT.md](TEST_REPORT.md) | `scripts/run-tests.sh` | Every unit and integration test, what each suite covers, and JaCoCo coverage |
| [SECURITY_REPORT.md](SECURITY_REPORT.md) | `scripts/security-scan.sh` | SQL-injection review (static and runtime), data-exposure controls, residual risk |
| [LOAD_TEST_REPORT.md](LOAD_TEST_REPORT.md) | `scripts/run-load-test.sh` | Migration, read, write and mixed workloads at 500k loans / 2M payments, with CPU, GC, contention and SQL timings |

Regenerate all three:

```bash
scripts/run-tests.sh
scripts/security-scan.sh
scripts/generate-load-data.sh   # ~30 s, writes a 1.3 GB H2 file under perf/data (git-ignored)
scripts/run-load-test.sh
```

## How to read the load numbers

One JVM, one H2 file database, one 8-core VM. H2 has no network hop and no durable commit, so the
absolute latencies are optimistic and the throughput is a lower bound on the *code*, not a
prediction of production. What does transfer is the shape: which query patterns collapse at scale,
how the write path behaves under contention, and where the machine saturates.
