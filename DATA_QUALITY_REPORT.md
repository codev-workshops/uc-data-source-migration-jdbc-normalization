# Data Quality Report — Legacy CDW → Loan Service API

Generated by `DataQualityReportService` (`GET /api/data-quality/report/markdown`) against the seed
data in `src/main/resources/data-legacy.sql`. Re-run the app and fetch that endpoint to refresh the
findings below; the JSON form is at `GET /api/data-quality/report`.

## 1. Transformation flow map

```
 CDW tables (H2, all VARCHAR)          Spring Data repositories            LoanService translation
 ───────────────────────────           ────────────────────────            ────────────────────────────────
 CDW_BORR_MSTR ───────────────▶ LegacyBorrowerRepository ─────────▶ toBorrowerDto()
 CDW_LN_PROD   ───────────────▶ LegacyLoanProductRepository ──────▶ (product description lookup)
 CDW_LN_ACCT   ───────────────▶ LegacyLoanAccountRepository ──────▶ toLoanSummary()
 CDW_PMT_HIST  ───────────────▶ LegacyPaymentRepository ──────────▶ toPaymentDto()
                                                                          │
                                       every String field passes through  │
                                       service/validation/FieldTransformer │
                                       ┌──────────────────────────────────┴───────────────────────┐
                                       │ AmountTransformer   ^\d{1,3}(,\d{3})*(\.\d{1,2})?$ …  │
                                       │ DecimalTransformer  rates / LTV                          │
                                       │ IntegerTransformer  credit 300-850, term 1-480, dlq ≥ 0  │
                                       │ DateTransformer     strict MM/DD/YYYY, real calendar      │
                                       │ CodeExpansionTransformer + LegacyCodeSet (exhaustive)     │
                                       └──────────────────────────────────┬───────────────────────┘
                                                                          ▼
 DTOs (value | null, plus dataQualityViolations[])                 REST endpoints
 ───────────────────────────────────────────────────               ─────────────────────────────────
 BorrowerDto    ─────────────────────────────────────────────────▶ GET /api/borrowers, /api/borrowers/{id}
 LoanSummaryDto ─────────────────────────────────────────────────▶ GET /api/loans, /api/loans/{id}
 PaymentDto     ─────────────────────────────────────────────────▶ GET /api/loans/{id}/payments

 Cross-record rules (DataQualityValidator + ReferenceResolver) read all four repositories and feed
 DataQualityReportService ───────────────────────────────────────▶ GET /api/data-quality/report[/markdown]
```

Contract: a field that fails transformation is `null` (amounts, rates, integers) or the literal
`"Unknown"` (codes) **and** an entry is appended to the record's `dataQualityViolations` array. The
former `BigDecimal.ZERO` fallback and raw-code passthrough no longer exist.

## 2. Rule catalogue

| Rule | Severity | Meaning |
|---|---|---|
| `AMT_MISSING` / `AMT_FORMAT` | ERROR | Null/blank or malformed money amount (comma grouping checked before stripping) |
| `DEC_MISSING` / `DEC_FORMAT` | ERROR | Null/blank or malformed rate / percentage |
| `INT_MISSING` / `INT_FORMAT` / `INT_RANGE` | ERROR | Null, non-digit, or out-of-range integer |
| `DATE_MISSING` / `DATE_FORMAT` / `DATE_CALENDAR` | ERROR | Null, not `MM/DD/YYYY`, or impossible calendar date |
| `CODE_MISSING` / `CODE_UNMAPPED` | ERROR | Code absent or not in the exhaustive dictionary → `"Unknown"` |
| `REF_MISSING` / `REF_ORPHAN` / `REF_AMBIGUOUS` | ERROR | FK key blank, unresolved, or resolves to >1 parent |
| `REF_DENORM_MISMATCH` | ERROR | Loan's denormalized borrower name differs from `CDW_BORR_MSTR` |
| `REF_DENORM_UNVERIFIABLE` | WARN | `BORR_SSN_LST4` cannot be checked against placeholder `BORR_SSN_ENCR` |
| `PMT_SUM_MISMATCH` | ERROR | principal + interest + escrow + late fee ≠ `PMT_AMT` |
| `LN_ACTIVE_DELINQUENT` | ERROR | `LN_STAT_CD = ACT` while `LN_DLQ_DAYS > 0` |
| `LN_ESCROW_NO_CONTRIBUTION` | WARN | `LN_ESCROW_BAL > 0` but every payment has `PMT_ESCROW_AMT = 0` |
| `BORR_SSN_PLACEHOLDER` | WARN | `BORR_SSN_ENCR` matches `ENC_XXX_*` — not a real hash |
| `PMT_SEQ_NBR_LOSS` | WARN | Modern `payments` has no `legacy_payment_id`; `PMT_SEQ_NBR` would be lost |
| `INPUT_MISSING` / `INPUT_FORMAT` / `INPUT_UNSAFE` | ERROR | API path variable blank, not `LN-YYYY-NNNNN` / `B-NNNNN`, or >20 chars / disallowed characters → HTTP 400 |
| `INPUT_NOT_FOUND` | ERROR | Well-formed API key resolves to no legacy row → HTTP 404 (payments: empty list) |

Record score = 100 − 25 × ERRORs − 5 × WARNs, floored at 0.

### API validation mode and the `DQ_INVALID_INPUT` quarantine

Every endpoint can run in validation mode: globally via `loanservice.validation.mode=on`
(default `off`) or per request via `?validate=true|false` (the query parameter wins). In this mode
the request's inputs are checked with the `INPUT_*` rules above, the records the endpoint returns
are run through the full rule set (including cross-table rules), and **every** violation is
written to the separate `DQ_INVALID_INPUT` table (`schema-dq.sql`) with the endpoint, input
name/value, entity type, record key, field, raw value, rule, severity, message and timestamp.
The response itself is unchanged, except that malformed inputs are rejected with 400.

| Endpoint | Purpose |
|---|---|
| `GET /api/data-quality/invalid-inputs` | Quarantined rows, newest first; filters `?ruleId=` or `?entityType=&recordKey=` |
| `DELETE /api/data-quality/invalid-inputs` | Clears the quarantine table |
